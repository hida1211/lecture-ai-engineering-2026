## 宿題

### 1. 基礎：学習率だけを変更

#### 変更と比較

`CONFIG["lr"]` を **`2e-4` から `1e-4`** に変更した。元の実行記録と基礎課題の `config` を比較すると、差分はこの1項目だけだった。学習前の21問の出力も両実行で一致していた。

| 条件 | 学習率 | 学習後 `format_rate` | 学習後 `content_rate` | 最後のTraining Lossログ（step 40） | 学習時間 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 元の設定 | 0.0002 | 100.00%（21/21） | 90.48%（19/21） | 0.013930 | 217秒 |
| 基礎課題 | 0.0001 | 100.00%（21/21） | 85.71%（18/21） | 0.031581 | 221秒 |

両条件とも40ステップ、20.0エポック。学習前は `format_rate = 9.52%`、`content_rate = 0.00%` だった。

#### 結果と考察

学習率を小さくしても形式正解率は変わらず、内容正解は1問少なくなった。両モデルの学習後出力が異なったのは「PDF 以外でも出せますか」の1問で、基礎課題ではFAQに提出形式の根拠があるのに `needs_review = true` が記録された。
根拠ありは15/15から14/15、根拠なしは4/6のままだった。
この20エポック・seed 42・21問の実験では、小さい学習率による改善は確認できなかった。学習時間の差は4秒。

### 3. 発展：用語集Q&Aの学習と用語集検索を比較

#### データと設定

講座の `scripts/make_sft_dataset.py` で用語集から `messages` 形式のQ&Aを作った。

```bash
uv run python scripts/make_sft_dataset.py > glossary_sft.jsonl
```

用語集は58語で、各用語に `「{term}」とは何ですか？` と `{term}について簡単に説明してください。` の2種類の質問を作り、合計116件とした。1種類目を学習用58件、2種類目を検証用58件とする分割を用いた。

生成上限 `max_new_tokens` を96から256へ変更し、学習率 `2e-4`、LoRA rank 16、alpha 32、seed 42、20エポック、最大系列長512を使用した。定義の説明に合わせて、学習前後とも `do_sample = false` で同じ条件を使った。

学習時間は 374.4秒、160steps、20.0epochs。最後に記録されたlossは 0.06697279214859009。

推論時のモデルへの入力は質問のみで、用語集の定義や参考正解は渡していない。JSONや `needs_review` の出力は要求せず、通常の文章として内容を評価した。

| ID・区分 | 質問 | 期待する回答の要点 |
| --- | --- | --- |

#### 検索方法と採点基準

比較対象は、質問文に含まれる用語名または別名を用語集と照合し、一致した項目の定義をそのまま返す仕組みとした。英数字の境界を確認し、長い一致を優先することで `QLoRA` を `LoRA` と取り違えないようにした。同じ長さなら質問内で先に出現した一致を優先した。一致がなければ「用語集に記載がありません。確認が必要です。」と返す。検索後のLLM生成は行っていない。

保存された回答を全文確認し、生成AIの補助を使って次の二値基準で採点した。

- 既知語・言い換え：主要概念が正しく、核心について重大な誤りや矛盾がないこと。参考正解との文言の完全一致は要求しない。
- 未登録語：意味や仕組みを確認できないと伝え、確認・追加情報を求めること。根拠のない定義や用途を作った場合は不正解。
- 部分的に正しい単語が含まれていても、説明全体に重大な誤りがあれば不正解。途中で切れた回答も、保存された範囲で評価する。

検索はA1・A3でLoRA、A2・A4でQLoRAの定義を取得し、A5・A6で該当なしと返した。二値採点上の退行はないが、前後とも不正解なので改善したとはいえない。

#### 結果の解釈と検索との比較

今回の6問では、用語集を学習した後も、正しい概念説明と未登録語への保留を確認できなかった。回答は短くなったが、概念の混同は残った。最後のlossが約0.067であっても、それだけでは評価質問に正答できるとはいえない。学習前の回答には途中で切れたものがあるが、切れる前から重大な誤りを含んでおり、長さ制限だけが不正解の原因ではない。

学習データには用語の定義だけを入れ、未知語に確認を求める例は追加していない。したがって、既知語の定義を学習するだけでは、今回の未登録語2問への適切な保留は得られなかったと考える。

| 観点 | モデルを学習させる方法 | 今回の用語集検索 |
| --- | --- | --- |
| 期待できる使い方 | 応答形式や説明の仕方をそろえる。十分な学習・評価により、表現の異なる質問への対応を狙う | 登録済みの用語名・別名から、定義を再現する |
| 今回の観察 | 正確な定義や未登録語への保留を確認できなかった | 定義4件と該当なし2件を期待どおりに返した |
| 情報の更新 | 更新したデータでの再学習と再評価が必要になる | 用語集を更新すれば、次の検索から更新内容を参照できる |
| 主な弱点 | 定義の混同や、未知の用語にもっともらしい説明を作ることがある | 未登録の別名や、用語名を含まない質問は今回の一致方式では拾いにくい |

今回の目的である「決まった用語の正確な定義を返す」用途では、まず用語集検索を使うのが適していると考えた。ファインチューニングを併用するなら、検索した根拠の範囲で答えること、形式を守ること、根拠がなければ保留することを学習・評価する設計が候補となり、今後の課題である。

### 4. ファインチューニングが向く場面・向かない場面

向く場面： 決まったJSONの出力、回答の書き方の統一、与えた資料に沿う回答手順など、繰り返し求める振る舞いを調整したい場面。今回の演習と実装では、学習後にJSON形式の合格率がともに100%となり、この用途での効果を確認できた。

向かない場面： 正確な定義や更新される事実を、学習だけで保持させて答えさせる用途。今回の発展では用語の取り違えや未登録語への創作が残った。またFAQ課題でも、形式が正しくても無関係な根拠を選ぶ例があった。正確性が必要な回答では、検索する資料・評価質問・保留の条件を整えることが必要だと考えた。
